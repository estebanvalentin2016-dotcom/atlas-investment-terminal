# v0.10 Opportunity Radar — first discovery increment

ATLAS opens on an automatic recent 8-K review queue. It calls the existing SEC endpoint sequentially for eight predefined liquid-company tickers (CRWD, NVDA, MSFT, AMZN, META, GOOGL, PLTR, AVGO) and shows source-linked, timezone-aware recent 2.02 earnings / 1.01 material agreement disclosures from the prior fourteen days. Earnings come first only as a **research-review priority**, never a bullishness score or profit forecast. Failed sources are surfaced, not replaced with fake data. The queue auto-populates when the screen opens and can be manually refreshed.

**Not yet included:** validated positive fundamentals, extracted guidance surprises, source-matched initial public news, current market quotes/remaining-upside estimates, overnight venue validation, multi-market expansion, background scanning, or automatic trading. The queue currently surfaces **leads**, not verified opportunities. Those are the next increments needed to satisfy the actual research objective.

This branch starts from the previously tested v0.9 branch while v0.9 remains unmerged. `npm.cmd run build` and `npm.cmd run test` must be run locally before any merge. The existing demo pages remain fictional.

## Broad discovery increment
The Opportunity Radar now fetches SEC market-wide daily master index files (seven calendar-day dates, with absent holiday/weekend indexes skipped), using `SEC_USER_AGENT` and SEC's company ticker directory to resolve symbols. Recent 8-K and 8-K/A links are returned, with source failures and partial coverage exposed and a ten-minute response cache. Up to 40 newest links are presented for review. This is much wider than the previous eight-ticker poll but **not full opportunity discovery**: SEC master indexes do not supply Item 2.02/1.01, reliable first-public timestamps, bullishness, forecast upside, or stock liquidity. Unlisted companies are excluded. The prior 8-ticker parser still exists for regression tests and other uses. Event analysis and positive-catalyst classification are next.

## Full discovery queue increment (October 15, 2026)
Live source inspection established that SEC daily master indexes use compact `YYYYMMDD` filing dates and include hundreds of ticker-matched 8-K records. The parser now converts valid compact dates to ISO without guessing invalid dates, and preserves the distinct index date. The discovery endpoint returns up to 1,200 unique leads (formerly capped at 40). The UI paginates 20 per page, supports ticker/company search and index-date filtering, and optionally shows only one filing per ticker. Raw filing counts are explicitly not an opportunity or bullishness score. Source coverage remains partial for HTTP 403 days, and the local scanner does not poll in the background.

**Next intended step:** evidence-based company event classification from authoritative disclosure contents (not just 8-K presence), followed by observed price-reaction and remaining-upside research, venue/liquidity checks, and transparent rejection reasons. Do not label an event bullish or actionable from an SEC form code alone.

## First evidence-review increment
The Opportunity Radar now exposes an on-demand **Review filing evidence** action for each indexed filing, plus a sequential batch convenience action for up to five currently visible filings. The dedicated Node server endpoint only accepts canonical SEC EDGAR text file URLs, limits payload size, validates recognizable SEC filing structure and treats HTTP access restrictions as unavailable rather than as negative evidence. It extracts short source excerpts for a small set of favorable and cautionary language patterns. Pattern matches are **unverified claims to investigate**: they are not evidence of realized materiality, a verified guidance beat, bullishness, remaining upside, execution feasibility, or a trade recommendation. The batch is an arbitrary visible-page sample, not a market-wide ranking or continuous scan. A source-access problem may prevent reviews entirely. Regression tests cover URL restrictions, mixed/negative language, malformed pages and restricted SEC access.

Next milestones: publisher-source/SEC exhibit grounding, issuer-stated quantitative surprises with audited baseline comparison, current price reaction, Robinhood order eligibility, explicit failure reasons, and broader selection beyond the initial review sample.

## Large SEC filing source handling
The BLK filing returned an oversize error against the original 2.5 MB hard cap. The source reviewer now processes at most the first 4 MB of response bytes with streaming limits. If more bytes exist or the SEC declares a larger Content-Length, the response uses `partial_text` and displays an explicit incomplete-review warning and the number of bytes read. It never represents absent phrase matches as negative evidence when the filing is truncated. Original SEC source URLs remain available for reading the complete filing. Larger exhibits may still be omitted, and real-world full source relevance may require separate retrieval of the issuer's primary 8-K/exhibit documents. Tests exercise oversized-prefix, complete-document, and partial-status behavior.

## Selected SEC document evidence (BLK follow-up)
The BLK 2026-10-14 full SEC submission was approximately 4.99 MB, and a 4 MB bounded prefix contained no matching favorable phrases. The review now attempts source-specific retrieval first: use the accession number parsed from the SEC source URL to locate the primary 8-K via `data.sec.gov/submissions/CIK*.json`, then use the SEC filing directory `index.json` to select up to two text/HTML Exhibit 99 documents. Retrieve only bounded source files, preserve separate source links for every excerpt, and show selection and metadata limitations. This is still selective, not exhaustive, and the phrase rules do not verify event polarity, significance, novelty, or remaining upside. If metadata/documents are inaccessible, the existing 4 MB bounded complete-submission prefix remains the fallback. No paid feeds and no automatic trading. No SEC access workarounds or user-agent spoofing.

## BLK earnings-disclosure interpretation increment
The October 14, 2026 BlackRock filing is an Item 2.02 earnings release with Exhibit 99.1 and a supplemental exhibit. A phrase-only review returned no positive patterns even though the issuer's press release states revenue and adjusted EPS growth, AUM, and net inflows. The reviewer now extracts 8-K item subjects and bounded source-linked numerical statements (revenue/EPS growth, net inflows, AUM), with up to two mentions per numerical category. These are **reported operating figures** only. No analyst-consensus comparison, event surprise, likely stock move, or remaining-upside conclusion follows from them. Source access may remain partial, and all figures require verification against the original exhibit. Regression tests include representative BlackRock disclosure statements and cross-document source attribution.

## Filing-date market context (v0.11)
Opportunity Radar cards now offer a user-initiated `Check filing-date price context` action. It reuses existing `/api/market/event?ticker=...&eventDate=...` to retrieve completed daily bars from the user's configured *free Alpaca IEX feed* for both the company and SPY. A new pure helper computes the preceding completed close, filing-date close if available, first completed close after the filing date, and latest completed close within that endpoint's bounded event window, plus same-date SPY return differences when benchmark sessions are available. The absence of bars, delayed IEX data, holidays, benchmark failures, or inadequate history must remain explicit. No consolidated tape, intra-day pricing, news release time, or paid data is implied.

Important causality limit: a filing date is **not** a validated first-publication timestamp. A filing could follow an earlier announcement or appear after market close; a same-date price change may have happened before release or for unrelated reasons. These figures are **price context**, not an event-attributed price impact, statistical alpha, beta-adjusted return, sentiment signal, estimate of remaining upside, or a buy/sell recommendation. Analyst consensus/expectation baselines are not yet connected; company-reported year-on-year growth alone is not an earnings beat. The next step should verify actual issuer release timing and a time-stamped external expectations baseline before interpreting surprises.

## Raw EDGAR acceptance-time alignment
The filing-date context module now has a separate on-demand SEC acceptance-clock inspection via `/api/opportunities/acceptance?url=...`. It reads no more than 96 KB of the canonical SEC full-submission source, requires a top-level `<SEC-HEADER>` containing `<ACCEPTANCE-DATETIME>YYYYMMDDHHMMSS`, and checks an accession number if present. That raw SGML value is treated as an Eastern *local clock*, not an unconditionally trustworthy UTC instant. ATLAS deliberately does not use `data.sec.gov/submissions` `acceptanceDateTime` for session alignment because third-party audits have reported erroneous UTC/ET labels in some submissions records.

The UI separately displays the acceptance clock, regular-session classification, first eligible **completed** IEX daily close, optional following completed close, stock and SPY relative returns, opening gap, and session open-to-close return. An after-close acceptance uses the NEXT actual completed trading session; the filing-date close precedes SEC acceptance. During-session acceptance uses that day's close if available, but clearly warns that baseline-to-close movement contains earlier pre-acceptance trades. Weekends and holidays are aligned using returned actual bar dates. If the SEC header, market bars, or matching SPY data are unavailable, display missing evidence instead of guessing.

**Limitations:** acceptance is NOT the original issuer/earnings press-release time; earlier dissemination remains possible. Price moves are descriptive and cannot be attributed to SEC acceptance without validated first-public announcement timing. There is no consensus surprise or remaining-upside evaluation yet. Every action is user initiated, uses the existing free Alpaca IEX market feed, does not place orders, and never claims instant alerts.

## Readability-first research UI (v0.12)
The user requested a more scannable interface: previous 10–13 px text and dense two-column event cards were too small, with too many equally emphasized caveats and SEC excerpts. New `src/readability.css` loads after the base stylesheet and increases navigation, buttons, captions, metric, and explanation typography. Opportunity Radar uses a three-number discovery overview and a spacious single-column research list. FilingEvidence leads with up to six source-linked operating figures in large metric tiles; SEC excerpts and document audits are behind native `<details>` toggles. PriceContext leads with the stock return and the comparison with SPY, but maintains visible warnings when acceptance timing and completed sessions do not support an attributed market reaction. Daily-bar details, opening gap, and source limitations are behind optional disclosure controls. These changes do not add investment scores, trading signals, or predictive ranking. Three rendering tests check headline-first ordering and disclosure presence. User build/test and screenshots remain necessary for full validation.

## Weighted fundamental rankings and semantic color (v0.13)
The Opportunity Radar now shows a **build a weighted research ranking** section above SEC filing queue. User enters 1–8 comparison tickers, clicks once to fetch public SEC company facts via existing `/api/sec/company`, and adjusts factor weights with sliders (default: revenue growth 30, free cash flow margin 35, net margin 20, user-supplied P/E 15). The SEC adapter now exposes `PaymentsToAcquirePropertyPlantAndEquipment` as capital expenditures. Rankings require matching annual period-end values for operating cash flow, capex, net income, and revenue, with FCF = operating cash flow minus capex; revenue growth requires consecutive annual revenue. Companies with stale filings (over 550 days), insufficient factor coverage, or fewer than two independently verified non-P/E factors remain unranked. Missing factors never earn points. P/E must be supplied by the user and remains explicitly unverified; ATLAS does not manufacture P/E from stale EPS or incomplete prices. Rankings are among the selected tickers only; no claim of a market-wide stock search, sector-neutral scores, validated predictive performance, or trade advice.

The filing evidence reader now colors **explicit revenue/EPS increases and net inflows green**, revenue/EPS decreases and outflows red; standalone assets under management and ambiguous or nonperformance figures remain neutral. Observed returns use sign-based colors, not predictions. SEC extractor includes reported declines and outflows. The ranking model and color semantics have regression tests. Do not treat the visual color as a trading recommendation. Next steps: source-confirmed and timestamp-aligned valuation ratios, debt and dilution factors, sector-normalized scoring, backtesting/out-of-sample validation, and broad catalyst screening.
